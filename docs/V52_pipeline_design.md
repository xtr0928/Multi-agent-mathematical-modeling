# V5.2 管线架构设计：参谋组 + 单一拍板者 + 产物回归门

> 版本 v5.2 · 2026-08-15 深夜定稿
> 触发：v5.1 产物经 v2.8 评审 47/100（成功参赛奖档），修订回路提至 50 后暴露根因——
> **"过程治理 ≠ 产物正确；四模型商议 ≠ 有人负责"**。
> v5.2 目标：把建模时间前置、把方案所有权收拢、把产物分数变成门禁。

## 一、v5.1 的三个致命教训（升级依据）

1. **验收测错了对象**：v2.8 验收标准测"评审能不能找到错"，没测"产物烂不烂"。→ v5.2 增加**产物分数回归门**。
2. **责任稀释**：四建模手商议 → 无一人对方案定稿负责，951 违规被三层人看见、零层人修复。→ v5.2 设立**单一拍板者**。
3. **写作环节无全局责任**：writer 拿注册表照抄，新旧值拼贴（−843.92/−675.54）、章节错乱、文献幻觉。→ v5.2 写作改为**模板+定稿装配**，writer 只做语言组织。

## 二、v5.2 阶段结构（9 阶段）

```
S0 读题解析（确定性+LLM）
  产出：要求单元、硬约束全集（D2 模板）、附件口径、题型判定
S1 参谋组（四模型，隔离实例，只交候选方案，不产定稿）
  产出：每个模型的方案摘要（每问方法/参数/依据）、分歧清单（冲突点显式列出）
S1.5 总设计定稿（单一拍板者）★ 核心新增
  自动模式：新开 DeepSeek 实例（零上下文，防路径固执）→ 总结所有方案、
            挑出/融合最优建模方案 → 《设计方案定稿》
  半自动模式：分歧清单 + 推荐方案 → 问博士拍板（博士修改/确认后才定稿）
  定稿内容：每问方法与依据、参数及理由、硬约束逐条处理方式、
            反直觉风险预判、数字口径（每个结论数字由哪份脚本产出）
  铁律：定稿即法律。后续任何阶段偏离定稿 = 作废重做。
S2 求解（按定稿逐问写求解器，数字全进 registry，SHA 防漂移）
S3 数值门禁（确定性代码）：重跑 SHA 全等 + 预测量级一致性 + 基准并置
S4 装配写作（重构）：模板 + 定稿 + 注册表 → 装配；writer 只做语言组织；
   AI 声明由 manifest 自动生成；文献白名单；[Cxxx] 标签自动剥除
S5 四评 v2.8（保留）：GLM / Kimi / 新开 DeepSeek 全权 + Qwen 影子校准阶梯，
   零上下文隔离、先验证后评分、扣分记录制
S6 自动修复回路（新）：评审修订单 → 易修复项走确定性 repair 节点，
   需重算项回灌 S2 触发 freshness 全链作废重算 → 再评审，直到收敛
S7 产物分数回归门（新，最终出口）：v2.8 评审分数 ≥ 上一版基线，否则产物不出管线
```

## 三、拍板者细则（S1.5）

| 模式 | 决策者 | 输入 | 输出 |
|---|---|---|---|
| 自动 | **新开 DeepSeek 实例**（隔离上下文，不带撰写阶段的任何历史） | 四份参谋方案 + 分歧清单 + S0 硬约束全集 + 关键数据复算摘要 | 《设计方案定稿》v1 |
| 半自动 | 博士 | 分歧清单（每条附参谋推荐 + 理由）+ 推荐定稿草案 | 博士修改/确认后的定稿 |

- 为什么必须是"新开"：撰写/参谋实例的上下文里带着自己的方案偏好，换题后容易路径固执；
  新开实例只带本场材料，总结与挑选更中立。
- 定稿产出后 **hash 登记**，任何下游产物引用定稿版本号；定稿被改 → freshness 判定下游全链作废。

## 四、产物分数回归门（S7 细则）

- 基线：每个赛题的上一版产物 v2.8 仲裁分（华数杯 C 当前基线 = 50）。
- 规则：新版产物评审分 < 基线 → 阻断交付，输出退化诊断（哪几维掉分、对应哪些改动）。
- 管线本身升级时同样执行此门：v2.8 评审能力验收（17 条命中 ≥14/17）与产物质量验收双轨并行。

## 五、铁律（写进 PROJECT.md，逐条落位）

1. 定稿即法律：S1.5 定稿是唯一真源，后续阶段不得自创方法/参数/口径。
2. 单一责任人：每问求解、每个数字、每段正文都有且仅有一个责任人（可追溯）。
3. 数字唯一入口：论文数字只从 registry 注入；writer 禁止生成数字/文献/声明。
4. 修一处 → 下游全链重做（freshness 已实现，v5.2 增加定稿节点）。
5. 产物分数进门禁：不过 S7 不出管线。
6. 零上下文隔离：参谋、拍板、四评、写作各实例互不带上下文（防路径固执与污染）。
