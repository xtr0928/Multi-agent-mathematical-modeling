## 0. 设计目标

一句话：**让管线保证"下限"（数字正确、格式合规、无编造），把"上限"（建模深度、论证质量）的预算还给模型本身。**

三个可测量的目标：
1. **数字矛盾归零**（①②③类冲突由脚本根治，种子库召回率 ≥95%）
2. **方法级缺陷前置拦截**（循环验证、不可识别当点估计等，在写论文前被拦截）
3. **内容供给保底**（每主结果必须有可视化，验证产物强制）

## 1. 历史教训基线（为什么 v5 需要这些机制）

### 1.1 三版管线的失败模式

| 版本 | 一句话定位 | 死因 |
|------|-----------|------|
| v2.2 | "什么都要"的理想架构（12 开源项目功能并集） | 无校准、功能堆砌、SHA 门禁纸面化 |
| v3.0 | O 奖正样本校准（437 篇精读 → 铁律） | 批测是自评口径（循环论证）；LLM 自查漏 8 处矛盾 |
| v4.0 | 负样本校准（华数杯 8 矛盾 → 门禁） | Goodhart：目标函数从"七维评分"换成"门禁零失败"→ 内容供给被压缩（12 页 0 图）；时钟被纠错循环吃光 |

### 1.2 三个结构性缺陷（三版共有）

- **缺陷 A：收敛门消灭多样性**。"差异<20% 收敛≤3轮"把多模型互证退化成单模型——互证的价值是"跑两个、报告两个、解释分歧"，不是谈判到共识。
- **缺陷 B：评审压在生产末端**。方法论级缺陷（循环验证）在写作前 8 小时就存在，却在 PDF 渲染完才发现——修复代价=重写整篇。
- **缺陷 C：内容质量不可脚本化**。哈希/数字一致可脚本化，但"循环验证"抓不住——LLM 评委命中率可能不到一半。出路是**把内容质量转译成可执行产物**（验证产物强制）。

### 1.3 五类冲突分类（v5 检测层的核心输入）

| 类别 | 病例 | 可机械化解？ |
|------|------|:---:|
| ① 同名数值不同值 | §2.3 说 264 淘汰周，§3.5 用 259 | 完全可脚本化 |
| ② 口径漂移 | 264/259 可能都对（含/不含退赛周）但无 scope 标注 | 可脚本化（scope 一等公民） |
| ③ 派生量算错 | "57.5% (149/259)" 需反算验证 | 完全可脚本化（sympy/算术反算） |
| ④ 定义漂移/论证依赖断裂 | §5 承认份额只识别到排序，§7 却拿点估计做回归 | 半机械化（依赖图 + caveat 传播） |
| ⑤ 强度失配 | 回归被写成因果（"age hurts fans"） | LLM 判断 + 强度清单压制，压不干净 |

**总原则：矛盾在生成时产生，不在审查时。** 散文不是主产物，**声明注册表（claims registry）是主产物**，散文只是注册表的渲染视图。

### 1.4 实战教训清单（来自历史会话，逐条可追溯）

1. **评审 skill 的定位**（2026-07-29 用户拍板）：评审 = 差距诊断仪，分数只是附带参照。真正交付 = 不足 + 差距 + 优化顺序。
2. **S 奖论文 38 分案例**（2026-08-12）：5 篇参考文献全部编造（CrossRef 实锤）；摘要-正文结论相反；循环验证（反演 votes→用 votes 预测淘汰）；缺 Memo/AI Report。→ 造假类必须是阻断级。
3. **华数杯 8 处数字矛盾**（2026-08-12~13）：81.9% vs 80.1%、5.88h vs 5.74h、-7.8% vs -4.6% 等，全部是"代码改了口径但论文旧值残留"。→ 动态读数 + SHA 门禁。
4. **独立性教训**（2026-08-13）：参考旧配方做"独立重做"不是独立——用户要求从题面+数据出发。
5. **编造拦截**（2026-08-13 本会话）：Memo 里"fan-save 降到 45%"被当场改为真实回放 56.4-56.8%。→ 每个数字必须来自运行输出。
6. **评审打分系统的 6 个问题**（2026-08-12）：立场错配（精读 vs 15 分钟扫描）、维度不独立、推测混入评分、无锚点、区分度未检验。→ LLM 只用于相对排序，不用于绝对打分。

## 3. V5 架构（Stage 0-7 + 卡 + 预算）

### 3.1 72h 竞赛时间窗 + 内容下限配额（双机制）

**数学建模竞赛 3 天（72 小时）**——时间约束真实存在，但预算分配原则是"把时间给深度推理，不给纠错循环"。

**时间窗分配**（三 Agent 商议优先，成文硬保底）：

| Stage | 时间 | 占比 | 说明 |
|-------|-----:|:---:|------|
| 0 进气 + 1 结构化 | 3h | 4% | 快，不纠结 |
| 2 三 Agent 商议 | 10h | 14% | 商议 2-3 轮，每轮三模型独立深推——**深度的主场** |
| 3 双轨迹执行 | 30h | 42% | 计算主体（含验证产物） |
| 4 产物级评审 | 4h | 6% | 有产物可看，高效 |
| 5 成文 | 18h | 25% | **硬保底**——v4 死于纠错吃光成文预算 |
| 6-7 一致性+末端对抗 | 7h | 10% | 纠错循环在此内，超时带风险交付 |

**自由推理原则**：reasoning_effort 拉满、商议轮次不设硬上限（2-3 轮自然停止）、三模型各用其深度优势。纠错循环设上限（20% 内），**超限时"带风险交付"而非"消内容保平安"**。

**内容下限配额**（与时间窗并存，防纠错吃内容）：

| 配额 | 下限 | 依据 |
|------|------|------|
| 正文页数 | ≥15 页（MCM 25 页上限内） | 437 篇 O 奖平均 27 页 |
| 图 | 每个主结果必须有可视化（不设张数上限） | v4 教训"12 页 0 图" |
| 独立模型 | ≥2 条路线（三 Agent 商议后选最强两条） | 多模型互证 16/16 铁律 |
| 验证产物 | 每路线必须带运行输出级验证 | P3 原则 |

### 3.2 Stage 明细

**Stage 0 进气**（保留 v4，便宜且对）
- mode.json（含本表的时间预算 + 降级规则）/ 官方模板快照 / input_manifest.json(SHA-256)
- 卡0：模板未就位不进 Stage 1（非内容阻断，保留）

**Stage 1 题目结构化**
- problem_analysis.json：Q1..Qn × {决策变量/约束/评价指标/数据映射}
- 赛题要求逐条对照表（门禁1 保留——"答非所问"是 triage 头号杀手）

**Stage 2 模型组合设计**（改：三 Agent 商议 Deliberation，取消收敛门）
- 三个建模手（DeepSeek V4 Pro / GLM 5.2 / Kimi K2.7 各一，不同模型家族错误去相关）**独立深度提案**
- **商议循环（2-3 轮，自由推理不设上限）**：
  - 第 1 轮：各自独立深推出完整方案（建模思路+公式+验证计划）
  - 交换：三方案互相可见，各自写出对其他两方案的批评（可识别性/基线/验证缺陷）
  - 第 2 轮：各自修订方案（回应批评、吸收优点），修订说明必须逐条引用被采纳/拒绝的批评
  - 可再迭代第 3 轮（交叉意见趋同时自然停止，**分歧不强制收敛**）
- 产出 model_route.json = **从三方案选最强两条独立路线 A/B** + divergence_report（分歧写报告）
- 每条路线立项时声明配套验证产物（反演→模拟恢复；预测→holdout；优化→约束审计+下界）
- rubric_alignment.json：评分点↔章节对齐（对着评分标准建模）
- 可选：人工签字 10 分钟
- **卡1【前移的方法论内容闸】**：审查每案的 可识别性/验证方案/基线（形式审查：验证方案有没有声明；实质审查留给 Stage 4 有产物时）

**Stage 3 双轨迹并行执行**
- 各自 Jupyter 真实执行 → 基线对照 → 验证产物 → 灵敏度矩阵 → results/*.json
- 卡2【确定性产物闸】：基线存在？验证产物存在且为运行输出？灵敏度矩阵存在？→ 缺产物阻断（此时还没写字，便宜）

**Stage 4 产物级评审（三模型独立评审 + 投票）**
- DeepSeek / GLM / Kimi 各自独立评审两条路线的 results bundle（对抗立场：证据回答了 Q1..Qn 吗？方法论缺陷？）
- 交换批评 → 综合修订单（并集或投票，平票派第四方）
- 分歧不收敛 → divergence_report.json（分歧是诊断信息）
- 锦标赛：三模型各自排序 → **投票选主线** → selection.json（LLM 只做相对排序，不做绝对打分）
- 打回此时代价 = 重跑分析（几小时），不是重写论文

**Stage 5 成文（视图）**
- build_report：数字全部动态读自 results JSON（v4 保留）
- **注册表驱动写作**（本会话修正的张力 3：注册粒度分层）
  - 注册范围 = 数值声明 + 结论性声明（50-80 条/篇），描述性散文不注册
  - 写第 N 节时 agent 拿到的是注册表子集 + 符号表，不是全文草稿
  - 新事实必须先注册（附 provenance），不允许散文凭空断言
- 终稿单作者全量重写（长上下文模型 + 完整注册表）——**重写实例不得参与后续声明抽取**（本会话修正的张力 2）
- 图：每个主结果必须有可视化（不设张数配额——配额催生水图）
- 摘要："每个主结论有量化支撑"，允许区间/不可识别声明作为合法结论形式（26C 教训）

**Stage 6 确定性一致性层**（v4 原样，否决权降级）
- hash → manifest → 渲染 → 四方核对 → 格式断言
- **门禁脚本挂进构建流程（build 钩子），不靠 Agent 主动执行**——MathModel-Skill 教训：guard 由 Agent 主动执行时，无硬机制阻止跳过（子代理深读发现）
- **三级新鲜度链**（升级自 v4 单层 manifest）：input_manifest↔清洗报告、run_manifest↔建模脚本/产物、门禁报告↔输入哈希（MathModel-Skill workflow_guard.py 设计）
- **造假类（数据/文献/版本号/漏问）→ 阻断**
- 其余（数字不一致/图缺失/页数）→ risk_report.json 随交付附出 + 扣分，不阻断

**Stage 7 末端对抗**（单轨迹时的保底，不能取消）
- 按题目路线加载攻击清单：估计类→循环性/可识别性/机械产物三问；优化类→约束真实性/下界；预测类→泄漏/分布漂移
- 只出修订单，打分只做相对用途

## 4. 核心新机制一：三个注册表 + 依赖图

### 4.1 结果仓 results/*.json（v4 已有，保留）
所有数字的唯一来源。散文禁止硬编码。

### 4.2 符号表 symbol_table.json
每个符号/术语一条：{symbol, 定义, 单位, 适用scope, 首次定义章节}。
写作 agent 只能引用表内符号；新符号必须注册。治"同名异义"。

### 4.3 声明注册表 claims_registry.json（核心中的核心）

```json
{
  "claim_id": "C0142",
  "section": "2.3",
  "sentence": "The cleaned panel has 264 elimination weeks",
  "type": "count",
  "predicate": "elimination_weeks",
  "value": 264,
  "scope": {"population": "含退赛周", "era": "all", "rule": "all"},
  "provenance": {"file": "results/panel.json", "key": "n_elim_weeks"},
  "caveats": [],
  "depends_on": []
}
```

**scope 是一等公民**：
- 同谓词 + 同 scope + 不同值 → 真冲突，脚本阻断（259 vs 264 的正确死法：注册阶段就不可能并存）
- 同谓词 + 不同 scope → 不阻断，但强制散文中出现口径说明句，缺这句才报
- 派生量必须能反算：149/259=57.53% ✓；232+31+1=264 ✓。反算失败 → 阻断（纯算术，零 LLM）

### 4.4 依赖图 + caveat 传播（治④，最值钱的一环）

- 每条 caveat 是注册表节点（"份额只能识别到排序信息，点估计不可解释"）
- 每条声明声明 depends_on；凡是依赖链上游挂着 caveat 的声明，散文中必须复述该 caveat
- 图遍历检查传播完整性 → 报 CAVEAT_DROPPED
- ④类矛盾从"靠悟性读"变成"图可达性问题"

### 4.5 ⑤类强度失配（压不干净，用清单压制）

- 声明标 strength ∈ {descriptive, associational, causal, validated}
- 证据标 evidence ∈ {replay, holdout, simulation, external}
- 规则表阻断越级（replay 证据不许用 validated 措辞；associational 不许用因果动词）
- 能抓 80%，剩 20% 写进风险报告，认栽

## 5. 核心新机制二：检测层（三模型 + 作者回避 + 种子库）

### 5.1 部署原则：错误去相关 + 作者回避

| 角色 | 部署 | 理由 |
|------|------|------|
| 声明抽取 ×3 | 三个不同模型家族独立抽取全文声明，取并集 | 漏抽一条=注册表有洞；不同家族漏抽模式不相关，并集召回率远高于单模型 |
| 分歧标记 | 三份结果逐条对齐，不一致的入"待裁决"队列 | 模型分歧处=大概率有歧义/矛盾处 |
| 终裁 | 投票；平票派第四方 fresh 实例 | 避免写作者自评 |
| 作者回避（铁律） | 写 §N 的实例不得参与 §N 的抽取裁决 | 自洽偏差：写出矛盾的模型倾向于把矛盾读成自洽 |
| 视觉核查 | 有视觉的模型读渲染后 PDF：图内数字 vs 注册表 | 图是注册表外最后一块飞地 |

**张力 2 的裁决**：终稿单作者重写与作者回避的冲突——裁决为：重写实例作废（不参与抽取），抽取用另外三个实例。单作者重写优先，因为"分节接力是矛盾的温床"比"少一个抽取模型"损失更大。

### 5.2 种子矛盾库注入式回归测试（不限算力最该花的地方）

1. 种子库：华数杯 8 处矛盾、259/264、28/34 vs 30/34、caveat 丢失案例……全部做成测试用例
2. 每轮管线跑完，注入 50 个已知矛盾测召回率——硬指标不是感觉
3. 漏检归因：抽取漏了？scope 没建模？裁决投错票？定向修
4. **自动扩充（本会话修正的漏 1）**：每次真实运行中漏检的矛盾（被外部评审/用户抓到的）自动入库，带"为什么漏检"归因标签
5. 交付附 risk_report.json：共检查 N 条声明、修复 M 处、检查器种子召回率 X%、残余风险在⑤类

### 5.3 修复回路：单点修复，不碰散文

定位到注册表冲突声明 → 回 results 仓核对真值 → 改注册表那一条 → 依赖图自动找出受影响声明 → 受影响段落按模板重渲染。一处修复，处处生效。

## 8. 明确不做的事

2. ❌ 不加 HARD FAIL 条目和评审维度——清单够长，边际为负
3. ❌ 不追求打分尺子精度——七维分只用于候选间相对排序；尺子重建（H/M 对照）是另一个项目

5. ❌ 不设图张数配额——"每个主结果有可视化"替代"图 ≥6"（配额催生水图）

## 9. 边界：能承诺什么，不能承诺什么

**能承诺**：
- ①②③类冲突归零（脚本），④类接近归零（图遍历+三模型抽取），种子库召回率可测量
- 方法级缺陷在写论文前被拦截（验证产物强制 + 卡1 前移）
- 内容供给保底（Stage 5 预算硬保底 25%）

**不能承诺**：
- "循环验证"类错误——它是方法本身错误，数字全自洽，一致性管线抓不住。靠卡1 方法论闸 + 验证产物（模拟恢复实验）解决，不靠一致性检测
- **"跑对了"**——哈希链只防篡改、不防错跑（MathModel-Skill 弱点分析的尖锐结论：Agent 用错误数据跑出结果并如实记录哈希，同样能过门禁）。哈希只能证明"跑过"，证明"跑对"靠验证产物（模拟恢复/holdout/约束审计）
- 论文上限——由模型能力和选题深度决定，管线只决定下限和方差
