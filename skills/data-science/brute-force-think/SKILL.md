# 暴力思考架构 — Brute-Force Think

## 核心原则

```
题目+数据 → 三方同时深度思考(不限时)
                ↓
         报错? → 重来，其他Agent等
                ↓
         三方全完成 → 交叉讨论优缺点
                ↓
         迭代优化 → 讨论→改进→再讨论
                ↓
         方案收敛 → 输出最终解
```

**关键**：不设超时，不催 Agent，质量优先于速度。

## Agent 阵容

| Agent | Profile | 模型 | 角色定位 |
|-------|---------|------|---------|
| ① 数学理论派 | glm-review | GLM 5.2 | 擅长公式推导、凸优化、概率建模、严谨性 |
| ② 综合推理派 | default | DeepSeek V4 Pro | 擅长全局架构、可行性评估、多模型整合 |
| ③ 创新发散派 | kimi-ocr | Kimi K2.6 | 擅长另辟蹊径、非常规方法、跨学科借鉴 |

> ⚠️ 不用 `kimi-coder`(K2.7)，那是编码专精。

## 执行流程

### Round 0: 派发题目（并行）

三个 Agent 同时收到**完全相同**的题目和数据描述。Prompt 模板：

```
你是一道数学建模竞赛题的独立解题者。

题目：[完整题目描述]

数据：[数据路径、字段说明、样本量]

请独立完成以下所有任务：
[列出每道小题的要求]

输出完整解题方案，包括：数学模型、公式、算法步骤、结果分析。
不要与其他 Agent 讨论，给出你认为最优的方案。
```

**派发方式**：三个 `hermes -p <profile> chat -q "..."` 并行后台运行。

**进度输出**：
```
📤 Round 0 — 三方独立思考
📤 [GLM 5.2] 正在思考...
📤 [DeepSeek V4] 正在思考...
📤 [Kimi K2.6] 正在思考...
```
每隔 30 秒输出 `⏳ [Agent名] 思考中 (已运行 N 秒)...`

### Round 0 异常处理

| 情况 | 处理 |
|------|------|
| Agent 报错退出 | 立即重启该 Agent，原 prompt 不变 |
| Agent 无响应 > 10 分钟 | 杀进程，重启 |
| Agent 连续失败 3 次 | 标记为 "不可用"，用其余两个继续 |

### Round 1: 交叉讨论

三方全部完成后，将彼此方案交换讨论：

```
━━━ Round 1 — 交叉讨论 ━━━

将 GLM 的方案发给 DeepSeek 和 Kimi：
"这是另一位解题者的方案。请指出：
1. 哪些地方比你的方案更好？为什么？
2. 你的方案中哪些比这个方案更好？
3. 你认为两者应该合并成什么样的最终方案？"

（三向交叉：GLM→DeepSeek+Kimi, DeepSeek→GLM+Kimi, Kimi→GLM+DeepSeek）
```

### Round 2: 共识提取

将所有交叉评论汇总，让三个 Agent 各自基于讨论结果**修订**自己的方案：

```
"综合其他两人的反馈，请修订你的方案。
保留你的优势点，吸收他人的优点，修正被指出的弱点。
输出修订后的完整方案。"
```

### Round 3: 收敛判断

比较 Round 2 的三个修订方案：
- 如果三个方案**核心方法一致**（差异 < 20%）→ 收敛成功
- 如果仍有重大分歧 → 再一轮讨论 → 修订 → 直到收敛或达到最大 3 轮

### Round 4: 最终输出

收敛后由 DeepSeek (综合推理派) 汇总输出最终方案：

```
"以下是三个 Agent 经过多轮讨论后趋同的解题方案，请汇总：
[粘贴三个方案]
输出统一最终方案，标注每部分的来源 Agent。"
```

## 完整时间线示例

```
00:00  Round 0 派发 — 三方并行思考
05:00  GLM 完成
07:00  Kimi 完成  
09:00  DeepSeek 完成 (最慢)
09:00  Round 1 — 交叉讨论
12:00  Round 2 — 修订方案
15:00  Round 3 — 收敛判断 → 一致!
15:00  Round 4 — 最终输出
```

总耗时约 15-20 分钟，产出经过三方交叉验证的收敛方案。

## 与 math-brainstorm 的区别

| | math-brainstorm | brute-force-think |
|---|---|---|
| 思考深度 | 快速构思 | **深度解题** |
| 讨论轮次 | 1 轮汇总 | **多轮交叉迭代** |
| 异常处理 | 无 | **报错重来** |
| 输出 | 思路方案 | **完整解题方案** |
| 适用场景 | 思路发散 | **竞赛解题** |

## 与 multi-agent-pipeline 的串联

```
brute-force-think（本架构）
    ↓ 产出：收敛后的解题方案
multi-agent-pipeline（编码架构）
    ↓ 按方案实现代码 + 生成图表
latex-paper-en / latex-thesis-zh
    ↓ 输出论文 PDF
```

## Pitfalls

- **GLM 慢不是 bug**: 深思考正常 3-5min。实测 T1 5m30s 产 406 行推导。
- **prompt 拆分**: >400 words → 拆成独立子任务并行。实测拆分后全在 2-5min。
- **Kimi K2.6 推理 / K2.7 编码**: 别混。
- **30s 轮询硬规则**: `process(action='poll')` 每 30s 一次。
- **最多 3 轮**: 不收敛由 DeepSeek 汇总标注分歧。
- **用户急 → 立刻 solo 交付**: 不从 round 0 继续迭代。
