## 一、官方评分机制（2019 Triage 指南原文实证）

**评委真实流程**（官方 Triage Judging Guidelines）：
- **7 档分类**：Disqualified（DQ）→ Unsuccessful（UN）→ Successful（P）→ Honorable Mention（HM）→ Meritorious（M）→ Finalist（F）→ Outstanding（O）
- **初评两读制**：每篇论文由 **2 位评委独立阅读**，2 读一致决定是否进入终审
- **时间极限**：每篇 **10-15 分钟（平均），上限 15-20 分钟**——比任何人的想象都短
- **淘汰率**：初评后 **60-80% 论文被淘汰**，仅 20-40% 进入终审
- **比例目标**：Meritorious 约 10%，Finalist/Outstanding 合计 <1%
- **7 分制打分**（官方评分表）：1-2 = Successful，3-5 = Honorable Mention，6-7 = Meritorious，7 = Finalist/Outstanding

**官方建模流程五要素**（triage 指南明确列出，缺任一要素都限制评分上限）：
1. Problem Restatement（问题重述）
2. Assumptions & Justifications（假设与论证）
3. Model Construction and Application（模型构建与应用）
4. Model Testing and/or Sensitivity Analysis（模型检验/灵敏度分析）
5. Analysis of Strengths & Weaknesses（优缺点分析）

**官方质量指标**（评委识别的高分信号）：
- 数学与科学的**正确应用**
- **探索深度**（depth of exploration）
- 建模流程的**完整性**（completeness of a recognized modeling process）
- 研究支撑的**合理引用与文档化**
- **创新且有洞见**的建模方法
- **清晰简洁的表达**（clear and concise exposition）

**官方 HARD FAIL 逻辑**（2019 C 题示例）：「Teams that fail to build this Spread Model can score **no higher than 2**」「fail to address both time and geographical dimensions **no higher than 3**」「good graphical results should be **scored higher**」——核心模型缺失 = 封顶 2 分。

## 二、评委评分维度（七维，权重为经验估计）

评委给每篇论文打分时，围绕 **7 个维度** 进行。满分 100，权重为经验值（官方不公开权重，此为本 skill 对标 O 奖论文反推的合理估计，**标注为估计值**）：

| 维度 | 权重 | 评委在问什么 | O 奖论文表现 |
|------|:--:|------------|------------|
| 1. 摘要与概述 | 15% | 一页内能否说清：问题+方法+关键数值+意义？ | 4 段式：挑战→方法→关键结果→意义，全部有数字 |
| 2. 建模合理性与创新 | 25% | 模型是否贴题？假设是否合理？是否有新意？ | 模型有「为什么选它」的理由 + 淘汰方法也提及 |
| 3. 问题解决完整性 | 20% | 每个子问题是否都被完整回答？ | 子问题↔模型↔结论一一对应，无遗漏 |
| 4. 分析与验证深度 | 15% | 结果有没有验证？灵敏度/鲁棒性有没有？ | 必有基线对比 + 灵敏度分析 + 误差讨论 |
| 5. 写作与表达 | 10% | 是否清晰、简洁、逻辑连贯？ | 每段一个信息，图表标题即结论 |
| 6. 图表质量 | 10% | 图表是否专业、信息量大、被正确引用？ | 每张图一个信息点，图注解释核心发现 |
| 7. 创新与洞察 | 5% | 有没有超出常规的见解？ | 至少 1 个原创洞察 + 可执行的建议 |

**评委真实心理**（2009 Judges' Commentary + 2019 Triage 指南实证）：
- 初评每篇论文平均 **10-15 分钟**，2 位评委各读一遍——「do not have a great deal of time」；
- **摘要决定生死**：「absolutely essential that a paper be well written and have a clear, concise summary to make it past the initial round」——摘要差 = 过不了初评；
- **摘要与正文必须一致**：「the summary and the rest of the paper must be consistent. Differences... do not make a positive impression」；
- **评委每年必谈灵敏度**：「Every year the judges explicitly discuss the issue of sensitivity and stability. The few teams that make a concerted effort to explore this aspect will almost always stand out」——官方原话；
- **基线验证加分**：「The few teams that did provide a confirmation of the numerical model made an immediate positive impression」；
- **图表必须融入叙述**：「figures and tables are part of the story... not something that stands apart」——孤立图表 = 无效；
- 评委先找「有没有明显硬伤」，再找「有没有亮点」——**消除硬伤比制造亮点更重要**；
- 评委喜欢「能一眼看懂」的论文；讨厌「需要替他找答案」的论文。

## 二、评委喜欢什么（正面清单）

### 2.1 摘要（最重要，15% 权重）
```
✅ 4 段式结构：
  段1 问题背景 + 技术挑战（为什么难）
  段2 本文方法（1-2 句，含模型名）
  段3 关键数值结果（必须有具体数字！）
  段4 意义 / 建议（对决策者的价值）

✅ 特征：
  - 每个 Q 都有对应结果数字
  - 不确定性/区间被报告（如"预测区间 [110, 313]"）
  - 300-500 字，一页内
❌ 摘要 = 论文目录（"首先…其次…最后…"）
❌ 没有数字的摘要（"结果表明模型有效"）
```
**O 奖摘要共性**：所有关键数字（误差、提升百分比、区间）都在摘要里出现，评委不用翻正文就能评估论文质量。

### 2.2 模型（25% 权重）
```
✅ 先声明模型类型："建立[线性规划/微分方程/XGBoost集成]模型"
✅ 完整变量表（符号、中文名、单位、类型）——评委最恨"变量不解释"
✅ 完整公式（目标函数 + 约束条件 + 参数定义）
✅ 每条假设注明：必要性 + 影响范围（"若放宽此假设，结论会…"）
✅ 方法选择说明：为什么用这个模型？淘汰了哪些方法？为什么？
❌ "建立了数学模型"（说了等于没说）
❌ 公式无编号、变量无符号表
❌ 假设凭空而来（"假设数据服从正态分布"——为什么？）
```

### 2.3 结果与验证（35% 权重 = 完整性 + 分析深度）
```
✅ 每个数值结果从 ≥3 个维度讨论（G5.2 规则）：
   ① 敏感性/鲁棒性（±10% 扰动下如何变化）
   ② 物理/领域含义（偏大偏小？合理还是意外？）
   ③ 基线对比（比简单方法好多少？）
   ④ 与文献/常识一致性
   ⑤ 误差与不确定性
✅ 必有基线对比："相比均值预测，RMSE 从 23.4 降至 15.1（-35%）"
✅ 灵敏度分析：关键参数 ±10%/±20% 的结果变化表
✅ 图表引用闭环：正文说"如图 3 所示" → 图 3 真的存在且支撑该句
❌ 只报结果不解释（"准确率 95%"——然后呢？）
❌ 无验证、无对比、无灵敏度
```

### 2.4 图表（10% 权重）
```
✅ 图表标题写结论不写内容：
   ❌ "不同模型的误差对比"
   ✅ "XGBoost 在阴天场景下误差降低 40%"
✅ 每张图一个信息点；一图多信息 = 评委看不懂
✅ 图注解释核心发现（3 行内）
✅ 三线表（顶线 1.5pt / 表头 0.5pt / 底线 1.5pt，无竖线）
✅ 字体清晰、坐标轴有单位、图例不重叠
❌ 花哨 3D 图（评委最恨的炫技）
❌ 截屏式图表、模糊图、无单位坐标轴
```

### 2.5 结论与洞察（5% 权重）
```
✅ 逐子问题直接回答 + 关键数字
✅ 诚实列出 2-3 条局限性
✅ 给决策者可执行建议（评委喜欢"所以你应该…"）
✅ 至少 1 个原创洞察（超出题面的发现）
❌ 空洞总结（"本文建立了模型，解决了问题"）
❌ 只写优点不写局限（评委一眼看穿）
```

## 三、评委讨厌什么（负面清单 / 常见扣分点）

### 3.1 硬伤级（直接掉到 H 奖以下）
| # | 硬伤 | 扣分理由 |
|:--:|------|---------|
| 1 | **编造数据/结果/参考文献** | 评委交叉验证时发现数字对不上 = 信任崩塌，直接最低档 |
| 2 | **摘要与正文数字不一致** | 摘要说 95%，正文说 93%——评委视为数据造假嫌疑 |
| 3 | **模型公式数学错误** | 维度不一致（左边是概率右边是人数）、定义域错误 |
| 4 | **子问题没回答完** | 赛题 4 问只答 3 问 = 完整性直接 20% 全扣 |
| 5 | **图表与正文矛盾** | 图 3 显示上升，正文说下降——必须一致 |
| 6 | **引用不存在的文献** | DOI 验证失败 = 学术诚信问题 |

### 3.2 中伤级（M 奖 → H 奖的分水岭）
| # | 问题 | 影响 |
|:--:|------|------|
| 1 | 无灵敏度/鲁棒性分析 | 分析深度扣半 |
| 2 | 无基线对比 | 无法证明模型优越性 |
| 3 | 假设不合理且无论证 | 模型合理性质疑 |
| 4 | 图表无引用/无解释 | 图表沦为装饰 |
| 5 | 摘要像目录 | 印象分大跌 |
| 6 | 变量无符号表 | 评委读不懂 = 直接跳过 |

### 3.3 轻伤级（M 奖内部的差距）
| # | 问题 |
|:--:|------|
| 1 | AI 写作痕迹（"首先…其次…最后""显著提高"） |
| 2 | 字数不足（每节低于 G5.1 下限） |
| 3 | 格式不统一（字体、编号、引用格式） |
| 4 | 缺少参考文献或格式混乱 |
| 5 | 结论没有回到原问题 |

## 四、打分体系（评审模式，v2.0 全题型校准版）

对论文按维度打分，输出结构化评审报告。**评分权重经 437 篇精读校准**——多模型互证与验证深度是 O 奖论文最大区分项，权重上调：

```
## 评审报告（总分 /100）
| 维度 | 得分 | 评价 | 关键证据 |
|------|:--:|------|---------|
| 摘要与概述 (15) | X | ... | 摘要有 ≥3 个数字/无数字（16/16 组铁律） |
| 建模合理性 (25) | X | ... | 模型类型声明/多模型互证/假设论证 |
| 问题完整性 (20) | X | ... | 子问题覆盖/交付物收尾 |
| 分析与验证 (15) | X | ... | 基线对比/灵敏度量化表/不确定性区间 |
| 写作表达 (10) | X | ... | 段落/逻辑/AI 痕迹 |
| 图表质量 (10) | X | ... | 图注/编号规范/三线表 |
| 创新洞察 (5) | X | ... | 原创概念命名/因果推断 |

## 判定档位
90+  → O 奖候选（Outstanding）
75-89 → M 奖（Meritorious）
60-74 → H 奖（Honorable Mention）
<60   → S 奖（Successful Participant）

## HARD FAIL 清单（任一命中直接降档，437 篇实证校准）
- [ ] 数据/结果/引用有编造痕迹
- [ ] 摘要与正文关键数字不一致
- [ ] 有子问题未回答
- [ ] 公式存在数学错误（维度/定义域）
- [ ] 图表与正文结论矛盾
- [ ] **全文仅 1 个模型且无基线对照**（16/16 组：多模型互证 100% 铁律）
- [ ] **摘要零数字**（16/16 组：数字摘要 100% 铁律）
- [ ] **灵敏度只声明不量化**（无参数-指标表/图，14/16 组）
- [ ] 数据缺失/假设简化无"仍可用"辩护（16/16 组）
- [ ] 图表无编号且正文无引用（11/16 组，扣分项）**

## 修改优先级（按扣分效率排序，437 篇实证）
1. 修复 HARD FAIL（优先！）
2. 摘要补数字（15% 权重，20 分钟可改）
3. 补基线对比（多模型互证，最大区分项）
4. 补灵敏度量化表（参数-指标）
5. 补数据辩护（缺失/假设的"仍可用"论证）
6. 图表编号 + 标题结论化
7. 原创概念命名（记忆点）
8. 变量表补全
```

## 五、评委视角写作要点（写作模式）

写论文时随时切换评委视角自问：

### 摘要自检
- [ ] 每段有没有具体数字？
- [ ] 有没有"有效/显著"等无数字空洞词？
- [ ] 是不是"挑战→方法→结果→意义"四段式？

### 模型自检
- [ ] 模型类型一句话声明了吗？
- [ ] 变量表完整吗（含单位）？
- [ ] 公式编号了吗？
- [ ] 每条假设有理由吗？
- [ ] 淘汰的方法提了吗？

### 结果自检
- [ ] 每个结果有 ≥3 维讨论吗（G5.2）？
- [ ] 有基线对比吗（数字形式）？
- [ ] 有灵敏度分析吗？
- [ ] 数字在摘要/正文/图表三处一致吗？

### 图表自检
- [ ] 标题是结论吗？
- [ ] 一张图一个信息点吗？
- [ ] 三线表吗？
- [ ] 正文引用了吗（"如图 X 所示"）？

### 结论自检
- [ ] 逐子问题回答了吗？
- [ ] 局限诚实列了吗？
- [ ] 给决策者建议了吗？

## 八、O 奖论文共性速查（437 篇全量精读：2012-2025 全题型）

### 8.0 全题型共识（18 组独立总评的统计——100% 全票项 = 铁律）

**优点模式（评委真正买账的）**：
| 模式 | 提及率 | 说明 |
|------|:--:|------|
| **多模型互证 + 交叉验证** | **16/16 (100%)** | 2-4 模型递进/互补链 + 与基线/ML 对照——O 奖第一铁律 |
| **数字密集型摘要** | **16/16 (100%)** | 摘要直接给 R²/误差/区间/概率，评委 30 秒看到工作量 |
| 真实/权威数据验证闭环 | 14/16 (88%) | WHO/World Bank/NASA/实测数据 + 回测/反事实对照 |
| 交付物文体化（Letter/Memo/报告） | 12/16 (75%) | 面向真实决策者收尾，全题型通用（非 C 题也大量出现） |
| 不确定性量化（Bootstrap/MC/区间） | 9/16 (56%) | 近年最强趋势，2023-2025 标配 |
| 原创概念命名 + 前置 | 6/16 (38%) | 记忆点（Subset Entropy/采样零/host boost） |
| 双轨/分层/模块化模型架构 | 7/16 (44%) | 两段式生成-评估、基础-高级分工 |

**弱点模式（O 奖也踩的坑，按严重度）**：
| 弱点 | 提及率 | 说明 |
|------|:--:|------|
| **验证弱/缺基线定量对比** | **16/16 (100%)** | 自模拟对比居多、统计对标不足——最大通病 |
| **数据缺/假设多/参数靠文献** | **16/16 (100%)** | 机理模型无实测校准、小样本——第二大通病 |
| 灵敏度流于调参声明 | 14/16 (88%) | 有灵敏度章节但给不出参数-指标量化表 |
| 图表编号/引用混乱 | 11/16 (69%) | 42 图无编号、59 图仅 1 编号等 |
| 权重主观（AHP/模糊/熵权） | 10/16 (63%) | 评价类题型通病，需校准或敏感性兜底 |
| 引用不规范（Wikipedia/知乎/重复） | 6/16 (38%) | 中文队高发 |
| AI 使用痕迹裸露 | 2/16 (13%) | 2025 起评审要求披露，附录贴 ChatGPT 记录可加分亦可减分 |

### 8.1 题型差异速查（全题型精读新增）

- **A 题（机理/物理）**：全机理建模（热力学/流体/结构）+ 商业软件求解（ANSYS 等）+ 正反问题（贝叶斯反演）；常见坑=参数靠文献、无实测校准
- **B 题（工程/运筹）**：优化调度 + 工程经济交叉（成本/保险/收益）；常见坑=约束简化过度
- **D 题（运筹/网络）**：交通/网络流 + 均衡模型（Wardrop/纳什）+ Gini 公平量化；2025 巴尔的摩题是典范（OSM 大数据预处理 35 万条）
- **E 题（环境/政策）**：生态估值 + 哲学框架（Georgism/QALY）+ 给决策者的信；常见坑=AHP 权重主观（E 题通病）
- **F 题（社科/政策）**：多准则评价 + 模拟仿真 + 政策建议；常见坑=评价类验证偏软
- **C 题（数据科学）**：见 8.4-8.5；近年（2023-2025）因果推断（PSM-DID/贝叶斯变点/ZINB）成显著特征

### 8.2 精读共识：3 个最强优点模式（C 题组详版）

**① 多模型互证 + 证据链设计（O 奖第一共性）**
- 不用单一模型打天下：2-4 个独立模型互相印证（2401298 动量=朴素二项残差再贝叶斯网络；2418251 相关系数 0.704/0.729 互证 RNN 与 SVM；2311035 Task 间结论互相一致；2318036 仿真聚类与 RF 分类互证；2505964 自下而上链路）
- 模型演进链叙事：先建简单模型→诊断发现问题→升级模型（2522820 Tobit 有异方差→层次混合效应；2212336 先证 ARIMA 只抓线性、LSTM 只抓非线性再组合）
- 与 ML/基准横向对比（1901679 随机游走 vs 空间回归；2501869 Hurdle vs Tobit vs RF/XGBoost）
- **模式：每个结论至少两个独立来源支撑**

**② 不确定性量化 + 诚实报告（近年最显著趋势）**
- Bootstrap 95% 区间（2500759、2510185）、Monte Carlo 1000 次（2505964）、随机扰动 1000 组"优于 93%"（2218743）、KL 散度敏感性（2109298）、150 次独立训练（2311035）、40% 子采样（2401298）
- 敢写负面结果：1901213"社会经济因素无法单独预测"、2109298"文本主题与分类无关"、2307946"数据增强反而失败"
- 统计严谨性作为卖点：Rhat=1+ESS 上万收敛诊断（2524070）、Sobol' 全局敏感性（2516695）
- **模式：敢写负面结果 + 数字化的不确定性区间**

**③ 面向决策者的"最后一公里"（C 题本质：数据→决策）**
- 约 20/30 篇以 Letter/Memorandum 收尾（给州长/教练/NYT 编辑/投资者/NOC/球员），把模型输出翻译成可执行建议
- 分级分人群带阈值的行动建议（55583 的 30% 临界点专用道；2524070 的 24.8% 首牌概率）
- 原创概念命名 + 前置宣传：Subset Entropy（2322645）、采样零/结构零（2524070）、importance vs influence（28747）、host boost（2503389）、BHDM（2513314）、动量=得分显著性方差（2410482）——**让评委记住你的记忆点**
- 摘要给数字、正文给机制、结尾给行动

### 8.2 精读共识：3 个常见弱点（O 奖也踩的坑）

1. **权重/参数主观设定**：31262 自认 α=β=γ=1/3 未经训练；C50193 承认 AHP 主观；C78577 承认效用函数与 ARIMA 阶数主观——凡权重靠拍脑袋必被评委看到
2. **摘要/正文缺数字、Strength/Weakness 模板八股**：早期论文（2012-2017）摘要定性叙事无精度无 p 值；超过一半论文 S/W 小节自我表扬+泛泛而谈（说"好"不给证据）
3. **数据妥协未解决 + 外部验证不足**：C73767 缺生产数据用消费替代、2010638 月度数据精度低、2004647 评分丢信息——可以承认妥协，但要给出"为什么仍可用"的辩护（区间化、敏感性兜底）

### 8.3 近年（2023-2025）新趋势：因果推断进竞赛

- 计量经济学因果框架：PSM-DID（2510862）、贝叶斯变点（2501869）、Tobit→层次混合效应（2522820）、ZINB 贝叶斯计数（2524070）
- 博弈论：纳什均衡分析（2406176 东道主设项、N-player 博弈）
- 图神经网络进竞赛：GNN 教练网络（2516695）
- 交叉验证正式选模（2517690 四模型十折 CV）而非拍脑袋

### 8.4 早期 C 题网络科学类特征（2013-2015 实证）

**早期 9 篇 C 题 O 奖全部为网络科学类题目**，共性建模路线：
1. 把现实问题抽象为**图/网络**（人物节点 + 关系边）——2013 犯罪团伙、2014 科研合作、2015 人才流动；
2. 用**中心性指标**（度/接近度/介数/特征向量）识别关键节点；
3. 结合**聚类/社团检测**分组；
4. 常引入**改进指标**（如 2014 的 Relation Distance Model = 三种中心性加权融合、CD-metric 合作距离）；
5. 用**文本/语义分析**增强（2013 用文本分析验证 SNA 结果）。

结构完整度示例（2014-25318，O 奖中最标准的章节模板）：
```
1. Introduction
2. Basic Assumptions
3. Definitions
4. [Model 1] Data Preprocessing → Model → Validation of the Model
5. [Model 2] Authority-Popularity Evaluation Model → Sensitivity Analysis → Strengths and Weaknesses
```

**官方评委评语（2009）额外证实**：
- 摘要三要素：问题概述 + 具体结论/建议 + 方法概述（官方原话："provide a brief overview of the problem... let the reader know their specific conclusions and recommendations... provide the reader with an overview of the approach"）
- 摘要不要堆背景和叙事（"such material in the summary can drastically reduce the space available"）
- 语法/标点/公式规范性差 = 过不了初评（"Teams that do not make use of proper grammar and punctuation are not likely to make it past the initial rounds"）
- 引用是「最珍视的原则之一」，评委能快速识别方法来源

## 八·五、国赛（CUMCM）评委视角 — 与美赛的关键差异

> 实证样本：国赛 2015 A 题特等奖论文全文（太阳影子定位，33 页）
> 国赛评阅标准官方不公开全文，以下结合论文实证 + 公开竞赛规范 + 行业共识，**标注证据等级**。

### 8.5.1 国赛摘要：逐问回答式（论文实证 ✅）

**国赛摘要必须逐问回答**，与美赛四段式完全不同：

```
✅ 国赛摘要结构（2015A 实证）：
   第一段：问题背景（一两句）
   然后逐问：针对问题一：……方法……具体结果……
             针对问题二：……方法……具体结果……
             针对问题三：……方法……具体结果……
             针对问题四：……方法……具体结果……
   最后：关键词：XXX  XXX  XXX（工具/方法/技术）

❌ 国赛摘要写成美赛式四段叙述 = 不符合国赛评委预期
```

实证特征（2015A 特等奖）：
- 每个问题都给出**具体数值结果**（"影长 9 点约 7 米递减到 12 点半约 3.6 米"）；
- 明确使用的工具（"利用 MATLAB 软件求解"）；
- 关键词列工具+方法+技术（"MATLAB 最小二乘法 视频解码器"）。

### 8.5.2 国赛论文结构：固定模板（论文实证 ✅）

国赛有相对固定的章节模板（2015A 实证）：

```
一、问题重述
二、问题分析
三、问题的假设
四、符号的说明
五、模型的建立与求解（主体，占全篇 60%+）
   （每问：建模思路 → 公式推导 → 求解过程 → 结果分析）
六、（模型检验/误差分析——论文中体现为误差讨论，不一定单列）
七、模型的优缺点
八、参考文献
九、附录（代码/数据）
```

### 8.5.3 国赛评分侧重点（行业共识 ⚠️ + 论文实证）

| 维度 | 美赛（官方 Triage 指南） | 国赛（行业共识 + 实证） |
|------|------------------------|----------------------|
| 结果正确性 | 重要（含在完整性中） | **极其重要**——很多题有参考答案或可验证的真值，算错=致命 |
| 灵敏度/鲁棒性 | **官方每年必谈**，缺了影响大 | 相对弱化——论文实证中 2015A 无灵敏度章节，但需有误差/验证讨论 |
| 创新性 | 明确列入质量指标 | 有加分但**不如结果正确性权重高** |
| 写作规范 | 强调简洁清晰 | 强调格式规范（摘要逐问式、符号表、文献格式） |
| 模型数量 | 1 个主线模型 + 验证 | **常见多个模型对比**（每问可能独立建模），"模型丰富度"是加分项 |
| 工具 | 不限 | 传统上 MATLAB 使用普遍（实证 2015A 通篇 MATLAB），Python 可接受 |

### 8.5.4 国赛评委特别关注（行业共识 ⚠️）

1. **结果是否算对**：国赛 C 类题常有标准答案或可交叉验证的数据结果；
2. **假设是否合理**：每条假设要论证必要性（"问题的假设"章节要写得有理有据）；
3. **问题分析是否透彻**：国赛特等奖的"问题分析"章节通常先给出解题思路的预分析（2015A 实证）；
4. **模型是否贴题**：不追求模型花哨，追求模型与数据/问题匹配；
5. **附录代码质量**：国赛要求提交代码，附录可读性影响评价。

### 8.5.5 国赛 vs 美赛写作清单对照

| 检查项 | 美赛 | 国赛 |
|--------|------|------|
| 摘要格式 | 四段式（挑战→方法→结果→意义） | **逐问回答式**（针对问题一/二/三…） |
| 摘要语言 | 英文为主 | 中文 |
| 灵敏度分析 | **必须有**（官方原话） | 建议有误差/验证讨论，不强求独立章节 |
| 章节结构 | 自由 | **固定模板**（重述/分析/假设/符号/建模求解/优缺点） |
| 模型数量 | 主模型 + 基线/验证 | 可多模型对比，每问独立建模 |
| 工具 | 不限 | MATLAB 传统偏好，Python 可 |
| 篇幅 | 25 页上限 | 通常 20-30 页（含附录） |

## 九、55 题实战评分校准（2026-08 批测，评分尺度实证）

55 题（2016-2025 全部真题）独立求解 + 本 skill 打分的分布，用于校准评审预期：

| 指标 | 数值 | 评审含义 |
|------|:--:|------|
| 平均 | 80.4 | 独立求解（无真人团队）的典型水平 = M 档中位 |
| 最高/最低 | 91（2017D 安检）/ 67（2019B 无人机）| O 档可达到，但需要真数据 + 外部锚点 |
| O 档（≥90）| 2/55 | 2017D（实测数据校准 + DES/解析互证 + R²=0.986）、2021D（真实音乐数据 + 音乐史吻合验证）|
| H 档（<75）| 6/55 | 主因：M2 互证失败（2021A）、交付缺失（2019B）、纯合成数据 + 简化机制 |

### 高分/低分的可操作信号（打分时对照）

**O 档信号**：真实官方数据 + 双模型互证（解析+仿真偏差 <5%）+ 外部锚点验证（实测/文献/历史事件吻合）+ 数字核对脚本全部通过 + 图 ≥5 张。

**M 档卡点（55 题中最常见）**：
1. 合成数据无锚点校准 → 验证维 11/15 封顶
2. 灵敏度只做 1-2 参数 → 扣 1-2 分
3. 图 3 张以下 → 图表维 8/10 封顶
4. 假设表缺逐条文献来源 → 建模维扣 1-2

**H 档红线**：互证失败未修复仍引用 / 子问题遗漏 / 无基线对照 / 交付物缺失（报告或图）。

### 评审时的分数校准建议
- 若论文满足：真数据 ✓ + 双模型互证 ✓ + 外部锚点 ✓ + 核对脚本 ✓ → 直接给 85+ 起评
- 若只有合成数据但机制完整 + 灵敏度矩阵齐全 → 78-82 合理
- 若报告/图缺失 → 先补交付再评分（2022B 补报告 43→70，差 27 分全在交付）
