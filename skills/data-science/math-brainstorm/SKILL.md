# 数模三人脑暴架构

## 架构

```
                     ┌─ ① glm-review (GLM 5.2)  ─┐
一道数模题  →         ├─ ② default (DeepSeek V4)  ─┼→ ④ 汇总 Agent → 统一方案
                     └─ ③ kimi-ocr (Kimi K2.6)  ─┘
```

**关键**：三个 Agent **并行同时**拿到题目，各自独立输出，互不影响。最后汇总合并。

## Profile 阵容

| Agent | Profile | 模型 | 角色 |
|-------|---------|------|------|
| ① | glm-review | GLM 5.2 | 数学理论派，擅长公式推导、模型选择 |
| ② | default | DeepSeek V4 Pro | 综合推理派，擅长全局把握、可行性分析 |
| ③ | kimi-ocr | Kimi K2.6 | 创新发散派，擅长另辟蹊径、非常规思路 |

> ⚠️ 不要用 `kimi-coder`（K2.7），那是编码专精，不擅长数学推理。

## 执行流程

### Phase 1：并行构思（三个 Agent 同时派发）

向三个 Agent 发送**相同的 Prompt**，各自独立输出解题思路：

```bash
# 三个并行派发
hermes -p glm-review chat -q "..." &
hermes -p default chat -q "..." &
hermes -p kimi-ocr chat -q "..."
```

**Prompt 模板**：

```
你是一道数学建模竞赛题的解题者。请阅读以下题目，输出你的解题思路。

题目：
[粘贴完整题目]

要求：
1. 为每一小题推荐适用的数学模型/算法，说明选择理由
2. 简述每个模型的关键公式或原理
3. 估计计算复杂度和可行性
4. 列出你的方案的优势和潜在风险

只输出解题思路，不写代码。
```

**进度输出**：每派发一个 Agent 输出 `📤 [Agent名] 正在构思...`，收到回复输出 `✅ [Agent名] 返回 (N 条思路)`。

### Phase 2：汇总合并

三个 Agent 都返回后，由 Default（或任一 Agent）汇总：

```bash
hermes -p default chat -q "
以下是三个 AI 对同一道数模题的独立解题思路，请汇总：

=== GLM 5.2 的思路 ===
[粘贴 GLM 输出]

=== DeepSeek V4 的思路 ===
[粘贴 DeepSeek 输出]

=== Kimi K2.6 的思路 ===
[粘贴 Kimi 输出]

请：
1. 提取三个方案中共同推荐的模型（共识部分）
2. 列出各方案独有的创新思路（差异部分）
3. 合并为一个完整的最终方案，标注每部分的来源
4. 给出方案优先级排序（首选、备选）
"
```

### Phase 3：方案输出

汇总后的最终方案应包含：

- **题目分析**：每道小题的解题方向
- **模型推荐**（按优先级）：首选模型 + 1-2 个备选
- **共识标记**：三人一致推荐的部分
- **创新亮点**：某人独到的见解
- **风险提示**：各方案提到的潜在问题

## 进度输出规则

```
━━━ [Phase 1/3] 三方并行构思 ━━━
📤 GLM 5.2 正在构思...
📤 DeepSeek V4 正在构思...
📤 Kimi K2.6 正在构思...
✅ GLM 5.2 返回 (3 条思路)
✅ DeepSeek V4 返回 (4 条思路)
⏳ 等待 Kimi K2.6...

━━━ [Phase 2/3] 汇总合并 ━━━
📤 正在汇总三方方案...
✅ 汇总完成：共识 3 项，差异 5 项

━━━ [Phase 3/3] 最终方案 ━━━
[输出完整方案]
```

## 使用建议

1. **先脑暴后编码**：本架构只负责解题思路，确定方案后再用 `multi-agent-pipeline` 编码实现
2. **题目要完整**：确保三个 Agent 拿到的题目完全一致，包括附件说明
3. **汇总要公平**：汇总 Agent 不能偏袒自己的方案，要客观合并
4. **保留分歧**：有争议的地方标注出来，供人工决策
5. **PDF 提取**：用 `pymupdf`(fitz) 提取 PDF → `uv pip install PyMuPDF`
6. **数据先行**：派发前用 `head`+`wc -l` 确认 CSV 规模，附在 prompt 中

## Pitfalls

- **GLM 最慢**：实测比 DeepSeek/Kimi 慢 40-80%（~4.5min vs ~2.5min），不要误判为卡住
- **Kimi 初始化慢**：Hermes 启动 Agent 需 30-60s，之后才开始输出
- **合并上下文爆炸**：三方输出可达 800+ 行，直接全量传给汇总 Agent 低效。建议先用 Default 提取每方 5-8 个关键要点（一句一要点），再汇总
- **Rank/Percent 赛季标注**：MCM 题目中两种规则切分赛季敏感，prompt 必须明确 S1-S2,S28+→Rank，S3-S27→Percent
- **不可上网搜题解**：COMAP 题目有版权，脑暴必须基于题目+数据本身

## 与编码架构的关系

```
math-brainstorm（本架构）
    ↓ 产出：统一解题方案
multi-agent-pipeline（编码架构）
    ↓ 按方案实现代码
最终论文/项目
```

两个架构可以串联使用：先用脑暴定方案，再用编码架构实现。

## 编码阶段过渡（2026-07-02 实战教训）

脑暴→编码的过渡是痛点：

- **脑暴 spec 直接当 GLM 输入**：如果脑暴汇总够详细（含公式+文件划分+函数签名），可跳过 GLM 第二次分析直接编码。
- **编码时 GLM 提示词分裂**：需 GLM 输出实现规格时，单 prompt 4 题会导致 GLM 卡 3+ 分钟 → 拆成每道题独立 prompt（≤300 words）并行派发。
- **Kimi 瓶颈**：Kimi K2.7 对 100+ 行规格也卡 2+ 分钟。3 分钟内无输出就 kill，切 Default solo。
- **Default solo 作为逃生口**：脑暴 spec + Default 直接编码是最可靠的兜底方案。
