# 2026 MCM Problem C 脑暴实战

## 题目摘要

Dancing With The Stars (DWTS) 投票机制分析：
- **数据**：421 条选手记录 × 34 赛季，含评委分 (1-10)、名人特征 (年龄/行业/地域)、职业舞者
- **核心挑战**：粉丝票数从未公开，需反推估计
- **两种投票结合方式**：Rank 法 (S1-S2, S28+) vs Percent 法 (S3-S27)
- **争议选手**：Jerry Rice (S2), Billy Ray Cyrus, Bristol Palin, Bobby Bones (S27)

## 四道任务

1. 估计每周每个选手的粉丝票数 + 不确定度量
2. 比较 Rank/Percent 两种方法对结果的影响 + 评委底部二人选择机制
3. 分析职业舞者质量和名人特征对成绩的影响
4. 设计更公平的投票系统

## 三方方案对比

### Task 1: 反推粉丝票数

| Agent | 方法 | 亮点 |
|-------|------|------|
| GLM | 线性不等式约束 + 多面体采样 (Hit-and-Run MCMC) → 贝叶斯 MCMC → 最大熵正则化 | 多面体几何解释不确定性 |
| DeepSeek | QP 约束优化 → Plackett-Luce 排名模型 + 时间-选手层级 MCMC | 完整贝叶斯层级模型 |
| Kimi | 线性可行性 → Bradley-Terry MLE → Hamiltonian Monte Carlo | 最大似然 + 贝叶斯双重验证 |

**共识**：贝叶斯 MCMC 是核心方法。先用线性约束缩小可行域，再用 MCMC 采样。

### Task 2: 投票方式比较

| Agent | 方法 | 亮点 |
|-------|------|------|
| GLM | 蒙特卡洛模拟 + Shapley 值分解 | Shapley 量化公平性 |
| DeepSeek | 反事实模拟 + FPI 指数 | FPI 粉丝力量量化 |
| Kimi | 反事实模拟 + 公理化比较 (Arrow 框架) | 公理体系评估 |

**共识**：反事实模拟是核心手段。争议选手个案分析 + 评委拯救机制模拟。

### Task 3: 影响因素

| Agent | 方法 | 亮点 |
|-------|------|------|
| GLM | SEM 中介分析 + 混合效应 + RF+SHAP | 明确两条路径分解 |
| DeepSeek | OLS/Logit → 分位数回归 → SEM | 捕捉异质性效应 |
| Kimi | HLM → Cox 生存模型 → SEM | 生存分析处理淘汰动态 |

**共识**：SEM 两路径分解（特征→评委分→名次 vs 特征→粉丝票→名次）。

### Task 4: 新投票系统

| Agent | 方案 | 亮点 |
|-------|------|------|
| GLM | 动态权重 + Borda+否决权 + Elo 评分 | 三方案递进 |
| DeepSeek | Z-Score 标准化 + 防垄断 + 超级否决 | 消除极端值 |
| Kimi | 自适应加权 + 累积 Borda 衰减 + 二次投票 | 二次投票防垄断 |

**共识**：标准化/规范化是方向。需模拟 34 赛季验证新方案。

## 成功要素

- **Prompt 要强调数据规模**：421 行 × 44+ 列，让 Agent 评估计算可行性
- **明确赛季划分**：Rank/Percent 分界必须写在 prompt 里
- **PDF 提取**：pymupdf 可靠，`fitz.open()` + `page.get_text()`
- **CSV 预览**：`head -3` 看字段名，`wc -l` 看行数

## 编码实现发现 (2026-07-02)

### T1 实现关键

- 纯线性规划解出多面体重心，早期周约束弱 → 重心偏极端
- **必须加正则化先验**：用评委分比例作 fan vote prior，LP 目标改为 `min ||x - prior||_1`
- 结果：2396 条估计，均值 4.67%，中位数 0.54%

### T2 结果

- FPI: Rank 0.958, Percent 0.793 → Rank 法确实更偏袒粉丝
- Jerry Rice (S2): 评委 22.5, 粉丝 9.4%, Rank 夺冠 / Percent 仅第 3
- Bobby Bones (S27): 实际夺冠，但模型估计两法下都 6-7 名 → 模型有偏或票数非线性

### T3 相关系数

| 因素 | → 名次(负=好) | → 评委分 | → 粉丝票 |
|------|-------------|----------|----------|
| 年龄 | -0.43 | +0.42 | **-0.32** |
| 舞者质量 | -0.47 | +0.39 | +0.28 |
| 运动员 | -0.08 | +0.04 | +0.05 |

> 年龄对评委分正面但对粉丝票反面：评委欣赏经验，粉丝喜欢年轻

### T4 ANS 参数

- α: 0.60(早期W1-3) → 0.42(中期W4-7) → 0.36(晚期W8+)
- 33.3% 的周次评委最高分 ≠ 综合胜者

### 代码坑汇总

1. `range(n)` 中 `n` 被 list comprehension 的循环变量遮蔽 → fix: `range(len(names))`
2. 粉丝票默认值 `1/n` 中 `n` 是 string → fix: `1.0/len(names)`
3. Git 日期 `2026-07-02 18:23:25 +0800` → `new Date()` NaN → `dateStr.slice(0,19).replace(' ','T')`
4. `git show --stat` 输出 `file | 3 ++--` 比 `--numstat` 更易正则解析
